2. tsvector: PostgreSQL’s text search vector type that represents preprocessed searchable content
A tsvector is PostgreSQL’s internal representation of a document optimized for searching. It’s not just a simple string — it’s a sorted list of lexemes (normalized words) with optional position information. Here’s a deep dive into tsvectors:
-- Simple tsvector exampleSELECT to_tsvector(&#x27;english&#x27;, &#x27;The quick brown foxes are jumping over lazy dogs&#x27;);-- Output:-- &#x27;brown&#x27;:3 &#x27;dog&#x27;:9 &#x27;fox&#x27;:4 &#x27;jump&#x27;:6 &#x27;lazi&#x27;:8 &#x27;quick&#x27;:2-- Example with multiple occurrences and positionsSELECT to_tsvector(&#x27;english&#x27;, &#x27;Running and running and running through the forest&#x27;);-- Output:-- &#x27;forest&#x27;:7 &#x27;run&#x27;:1,3,5-- Combining fields with different weightsSELECT setweight(to_tsvector(&#x27;english&#x27;, title), &#x27;A&#x27;) ||       setweight(to_tsvector(&#x27;english&#x27;, content), &#x27;B&#x27;) AS weighted_documentFROM (    SELECT &#x27;PostgreSQL Search Guide&#x27; as title,           &#x27;Learn how to search in PostgreSQL effectively&#x27; as content) t;-- Output:-- &#x27;guid&#x27;:3A &#x27;postgresql&#x27;:1A &#x27;search&#x27;:2A &#x27;effect&#x27;:6B &#x27;learn&#x27;:4B &#x27;postgresql&#x27;:7B &#x27;search&#x27;:8BThe numbers after each lexeme indicate their positions in the original text, and letters (A, B, C, D) indicate weights for ranking purposes.
3. tsquery: The query type used to perform the search
Tsquery represents a search query in a format that can be efficiently matched against tsvectors. It supports various operators for complex searches:

This function is designed to handle various search scenarios, from simple keyword searches to complex filtered queries with pagination. By consolidating all search-related logic into a single function, we maintain a clean API while providing powerful search capabilities that can be easily extended or modified as requirements evolve.
The function takes multiple parameters to support flexible search operations. The primary search_query parameter handles the full-text search terms, while optional filters allow for refined searches based on categories, tags, authors, and date ranges. To manage large result sets efficiently, the function implements pagination through page_size and page_number parameters, defaulting to 20 results per page.
